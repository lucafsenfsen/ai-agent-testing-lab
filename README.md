# AI Agent Testing Lab 2.0

Independent, open-source research into how reliably AI coding agents produce working applications. Phase 1 adds reproducible browser testing to an existing HTML/CSS/JavaScript evaluation dashboard.

**This is not an official OpenAI benchmark. The 96.8/100 evaluator score and the 50/50 automated result measure different things.**

## Experiment 001: three separate evidence records

The preserved application was generated by GPT-6 Astra High in ChatGPT Work. Its historical research record reports a completion time of **7 minutes 24 seconds** on October 8, 2026, with no human-requested revisions.

| Evidence | Result | Interpretation |
|---|---:|---|
| Original evaluator assessment | **96.8/100** | Subjective weighted ratings of one generation run; not an automated score |
| Original manual functional checks | **9/9 passed** | Historical human evaluation recorded in the experiment README |
| Phase 1 automated browser checks | **50/50 passed** | 25 cases executed in Chromium and WebKit against the preserved app; zero failed, errored, or skipped |

The timing and manual assessment come from the [original research README](Experiments/001-todo-gpt6/README.md), which is preserved unchanged. They were not remeasured by this browser suite. The automated checks are later tests of that same app, not 50 independent model generations.

Inspect the [individual automated results](results/experiment-001/evaluation.json), the [evidence notes](results/experiment-001/README.md), and the [unchanged generated source](Experiments/001-todo-gpt6/). Dashboard software QA is reported separately in [dashboard-qa.json](results/experiment-001/dashboard-qa.json); it does not increase the app's benchmark count.

## Reproduce the tests

Prerequisites: **Node.js 22+ with npm**, a Playwright-supported operating system, and network access for the initial dependency/browser downloads. The recorded run used Node 24.19.0, Playwright 1.64.0, and Apple Silicon macOS. Linux or Windows execution has not been independently verified in this release.

```sh
git clone https://github.com/lucafsenfsen/ai-agent-testing-lab.git
cd ai-agent-testing-lab
npm ci
npm run browsers:install
npm test
```

These checkout instructions apply once Phase 1 is merged. Before publication, run the same npm commands inside the prepared release folder.

`npm test` runs the Node logic checks, the app evaluation, and dashboard QA. Each browser case gets a new disposable context. A loopback-only server uses a free port and closes after the run. No API keys, model subscription, personal browser profile, administrator permissions, or security-setting changes are required. If an operating system lacks Playwright prerequisites, use a supported environment; the project does not install system packages.

```sh
npm run test:todo                         # Full 50-check application evaluation
npm run test:dashboard                    # Separate dashboard regression checks
npm run test:unit                         # Scoring, validation and report logic
npm run test:todo -- --project=webkit      # Partial suite; not the 50-check result
npm run test:todo -- --grep=T07            # Focused filter regression checks
```

Run `test:todo` first if running dashboard QA separately: two integration cases per engine require a real locally generated report and otherwise explicitly skip. See [the reproduction guide](docs/REPRODUCING.md) for exact coverage, status definitions, artifacts, replay and troubleshooting.

## Open the dashboard

```sh
npm start
```

Open [http://127.0.0.1:8765/](http://127.0.0.1:8765/). If that port is occupied, choose another, for example `PORT=8766 npm start` on macOS/Linux. Each browser and origin has separate saved evaluator records.

The dashboard retains five challenges, result recording/editing, weighted scoring, model comparison, browser-local storage, JSON import/export, and CSV export. **Automated tests** adds:

- **View published Experiment 001**: the fixed, reviewed public JSON evidence.
- **Load latest app evaluation / dashboard QA**: your most recent local run, including failed runs.
- **Open report JSON / Download this report**: inspect or transfer a saved normalized report.

Reports never create evaluator records or alter scores. The public dashboard is static: it displays evidence, but does not execute Playwright or call an AI model. Saved manual records stay in each visitor's browser; this is not a shared results database. Browser-data clearing can remove them, so export backups.

## Methodology

The question is: **How reliably can an AI coding assistant build, debug and improve functioning software under documented conditions?**

Phase 1 is a post-hoc evaluation of a preserved to-do app. The tests were written with access to its source. Test assertions cover task creation, editing, cancellation, completion, deletion, filters, persistence, invalid input, duplicate task identities, safe text rendering, text-length limits, storage faults, and responsive behavior at 320, 390, 768 and 1440 CSS pixels.

Playwright runs with one worker, no automatic retries, a fixed locale/timezone and pinned dependencies. Reports retain each case's pass/fail/error/skip status, original attempt status, timing, browser version, execution settings, and SHA-256 source/test hashes. Hashes verify that the original app and research README did not change during evaluation. No app changes were made to get the tests to pass.

Every attempted local browser run receives its own output directory. The latest pointer includes failures, not just successful runs. Initial Phase 1 test-development failures are disclosed in the evidence notes; they were corrected in the testing infrastructure and retained locally.

For future comparisons, freeze the task prompt, starter files, test protocol, tool access, time/retry budget and human-assistance policy **before** generating apps. Record exact model versions and generation conditions, retain unsuccessful generations as well as successful ones, and repeat runs. This release does not automate model generation.

### Subjective scoring

The original evaluator ratings were correctness 100, instruction following 100, reliability 90, and code quality 92. The dashboard weights are:

| Criterion | Weight |
|---|---:|
| Correctness | 40% |
| Instruction following | 25% |
| Reliability | 20% |
| Code quality | 15% |

`100 × 0.40 + 100 × 0.25 + 90 × 0.20 + 92 × 0.15 = 96.8`.

These ratings are evaluator judgments. Passing 50 browser checks does not independently establish code quality, imply 100/100, or revise the historical 96.8. Optional manual passed/total fields are also distinct from imported automated evidence.

### Scope and limitations

- **One generated app, one model generation.** Browser repetition is not evidence of generation reliability or a general model ranking.
- **Source-informed, post-hoc tests.** This is not a blinded or held-out benchmark. Freeze a shared protocol before future comparisons.
- **Finite coverage.** Passing these checks does not prove bug freedom, security, full accessibility, performance, or visual quality. There is no comprehensive accessibility audit or stress test.
- **Browser-engine checks.** WebKit is not the installed Safari app; viewport resizing does not verify real-device touch behavior. Firefox is not included.
- **Persistence scope.** Reload and a new same-origin tab are checked. Browser-restart persistence and live cross-tab synchronization are not claimed.
- **Variable runtime.** Run IDs, timestamps, ports, task IDs and durations can differ. Reproducibility means comparable methods and observable assertions, not identical report bytes.
- **Historical claims.** Original timing and human checks are preserved as reported, not retrospectively remeasured. Imported reports are structurally validated, not independently authenticated.

The other planned challenges—calculator debugging, a memory game, a data dashboard, and improving an existing app—remain dashboard entries. Phase 1 does not claim automated app coverage for them.

## Public evidence and privacy

The public package contains source, tests, dependency manifests, documentation, the original preview, and reviewed normalized JSON reports. Public report exports omit local server URLs, screenshots/attachment paths, raw logs, traces, and input snapshots. The exporter records the original report's SHA-256 and documents the omissions; individual outcomes, timings and browser environment data are retained.

`node_modules/`, browser downloads, raw `reports/`, `work/`, release staging, editor settings, credentials and local backups are excluded. There is one direct development dependency: pinned `@playwright/test`; the dashboard has no runtime npm dependencies. The existing MIT copyright attribution is retained.

Use [PUBLICATION.md](PUBLICATION.md) and [release-files.txt](release-files.txt) to prepare a reviewed publication. Nothing in the build or test commands pushes to GitHub. Do not upload the entire personal working folder.
